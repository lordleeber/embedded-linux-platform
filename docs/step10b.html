OLED：把字畫成 pixel

SSD1306 不認得字。Step 10-a 的 driver 只收整張 1024 byte 的畫面，所以「顯示 EDGE」其實是先在 userspace 把每個字查表、變成一排排的點，畫進那 1024 byte，再整張寫下去。這一步做了一套 5x7 的 ASCII 字型和畫字的函式，並處理邊界：一行太長、字跨過 page、表裡沒有的字元。另外結掉 10-a 留下的一筆帳：OLED 在兩次寫入之間斷電又接回時，螢幕會一直黑著。

10b.1起點為什麼

螢幕只有點，沒有字

Step 9 的筆記說過：把 ASCII 的 'E'（0x45）寫進 SSD1306，只會在畫面上點亮一個 column 裡的 3 個點（0x45 = bit 0、2、6）。晶片沒有字型 ROM，字形要由送畫面的人自己決定。Step 9 只為 EDGE 準備了 D、E、G 三個字，Step 10-c 要顯示電壓、電流、功率，需要數字、字母、小數點和單位。

這一步要決定兩件事：字型和排版放在哪一層、邊界怎麼處理。phase04 的說法是「把 rendering 和 I2C transport 分開，避免 driver 變成一個巨大混合物」。所以 字全部在 userspace 畫，driver 一行都沒有為文字改。它仍然只收整張畫面，多一個 text ioctl 只會把字型和排版規則鎖進 kernel 的 ABI。

互動雙方：和 Step 10-a 相同。controller 是 c240000.i2c（i2c-1，100 kHz），target 是 SSD1306（0x3C）；userspace 的 edge_oled_ctl text 經 /dev/edge_oled 交給 edge_oled.ko。新的是 userspace 裡的 apps/oled_text.h，它沒有任何 I/O，只把字串變成 frame。這一步不做：讀 INA219、週期刷新（都是 Step 10-c）。

5x7 字型
每個字 5 個點寬、7 個點高。存法是「每個 column 一個 byte、bit 0 在上」，和 GDDRAM 的 byte 方向一樣，所以一個 column byte 可以直接搬進畫面，不用轉置。
字格（cell）
一個字佔的格子：6x8 = 5x7 的字加右邊 1 個點、下面 1 個點的空隙。128x64 的面板剛好放 21 欄 x 8 行（21 x 6 = 126，右邊剩 2 個點）。
clipping（裁切）
畫到面板外的點直接丟掉。和「換行」（wrap）不同：裁切後這一行的其他字位置不變。
glyph
字型裡一個字的點陣資料，這裡就是那 5 個 byte。

10b.4排版畫進 frame

draw_char：一次一個點，邊界交給 set_pixel

最直接的寫法是把 column byte 整個 OR 進畫面（frame[page * 128 + x] |= g[col]），只在 y 是 8 的倍數時才成立。這裡一個點一個點畫，y 是任何值都對，跨 page（10b.3 的 y = 4）不用特別處理；裁切也不用另外寫，set_pixel()（Step 9）本來就拒絕面板外的座標。代價是每個字跑 35 次迴圈，一張畫面最多 168 個字，和 99 ms 的 I2C 傳輸比起來可以忽略。

10b.6driver斷電之後

從 10-a 帶過來的：ACK 了，螢幕卻是黑的

Step 10-a 的 driver 只在「傳輸失敗」之後重送 init。10-a 那章已經指出盲點：OLED 在兩次寫入之間斷電又接回，中間沒有人寫，driver 就不會知道。接回的晶片回到 power-on reset（display OFF、charge pump 關），下一次寫入的每個訊息都 ACK，可是只送了畫面。這在 10-a 是推論，phase04 要求先寫重現步驟，再改。

能不能偵測？SSD1306 在 I2C 模式下讀不回 display RAM（Step 9 的筆記），這個 driver 也沒有任何讀取路徑可以問「你是不是剛被 reset」。剩下的做法是每次都重送設定。成本是 init 序列 24 byte（去掉開頭的 Display OFF）和 1 byte 的 Display ON，兩個訊息連同位址與 control byte 共 29 byte，100 kHz 下約 2.6 ms：

兩個細節：

  • 為什麼要跳過 Display OFF。init 序列的第一個 byte 是 AE（Display OFF），照抄的話每次刷新都先關掉面板、送完 99 ms 的畫面再打開，等於每次刷新閃一下黑。initialized 的意思因此改成「上一次 flush 讓面板亮著」：亮著就從第二個 byte 送起；第一次（probe）和任何失敗之後才送完整的序列，舊的 RAM 內容不會閃出來。驗收時連續刷新 5 次，人確認沒有閃黑。
  • 對亮著的面板重送設定安全嗎。送的值和現在的值相同（同一份序列），charge pump、contrast、addressing 都不會改變；被別人改過的（例如 oled_probe --force 送了反白）反而會被蓋回來。後者是推論，這一步沒測。

改完之後的不回歸：Step 10-a 的驗收腳本（--no-unplug）全過，唯一變的數字是每張畫面 96.4 → 99.2 ms，多的 2.8 ms 對得上多送的 29 byte 與兩次 START / STOP。

畫面沒閃，卻記了一個 FAIL；人看漏任何一件事就答 n。
正解
按 Enter 前先把 REFRESH 0/5 畫上去，每秒一次，題目只問閃黑。先寫測試看紅燈才改腳本。

這一步做到了什麼

Step 10-c 把 Step 8 的 hwmon 讀數接上來：一個 userspace 程式每秒讀 in1_input、curr1_input、power1_input，用 draw_text_at 排成固定的幾行，整張寫進 /dev/edge_oled。這一步選的「截斷不換行」和「每次重送設定」都是為它準備的：數字變長時版面不亂，OLED 鬆脫再接回時下一秒就恢復。

1. 為什麼在第 4 欄寫 "A\nB" 時，B 落在下一行的第 4 欄，而不是第 0 欄？

draw_string 遇到 \n 時把 x 設回呼叫時給的起始 x（cx = x），y 加 8。這樣從某一欄開始的多行文字會左邊對齊。

2. 字串裡有一個中文字「電」（UTF-8 三個 byte），edge_oled_ctl 會報幾個 unsupported？畫面上有幾個方框？

3 個、3 個方框。glyph() 一次看一個 byte，三個 byte 都 ≥ 0x80，各自畫成一個方框、各佔一個字格。

3. driver 每次 flush 都送設定，為什麼第一次（probe）還要多送一個 Display OFF？

probe 時面板上可能還留著別人畫的東西（10-a 驗收時是反白的 EDGE）。先關顯示、送完新的畫面再開，舊的 RAM 內容就不會在設定生效的那一瞬間閃出來。之後面板上一定是自己送過的畫面，就不需要了。

4. 只看 I2C 有沒有 ACK，能不能判斷 OLED 是否被 reset 過？

不能。reset 後的晶片照樣 ACK 每一個 byte，只是 display OFF、設定回到預設值。SSD1306 在 I2C 下又讀不回 display RAM，driver 沒有東西可以查，所以選擇每次都把設定送一遍。
