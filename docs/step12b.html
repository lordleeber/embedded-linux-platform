ADC 與按鍵：第一個會變的值

12b.1起點為什麼

driver 要讀的是外面世界的值

Step 13 的 kernel driver 要把 STM32 變成 Linux 看得到的裝置。一顆只有版本號和一顆 LED 的周邊，driver 寫了也沒什麼可讀。這一步把 12-a 預留的 0x10–0x1F（感測與輸入）填上四個 register：

  • ADC：PA0 上的電壓，12 bit，一個 byte 放不下，所以分成 ADC_LOW、ADC_HIGH 兩個 register。這是 register map 裡第一個多 byte 的值，12-a 寫下的 little-endian 和 auto-increment 規則第一次派上用場。
  • 按鍵：PA1 上的按鍵，BUTTON_STATE（現在按著沒）與 BUTTON_PRESSES（開機以來按了幾下）。

兩者都在 firmware 內部「自己變」：ADC 每 21 µs 換一個值，按鍵狀態每 1 ms 檢查一次。Jetson 讀到一半時值變了，這件事 12-a 從來不用擔心，這一步要處理。

互動雙方和 12-a 一樣：Jetson 的 i2c-1（c240000.i2c，100 kHz）是 controller，Blue Pill 的 I2C1（0x42）是 target，Jetson 這邊仍然只用 i2c-tools。新的是 MCU 內部的兩條資料來源（ADC1、SysTick）和麵包板上的新接線。這一步不做：Linux kernel driver（Step 13）、SPI、DMA、按鍵主動通知 Jetson（target 不能自己發起 I2C）。

ADC
analog-to-digital converter：把腳位上的電壓換成數字。F103 的 ADC 是 12 bit，0–4095 對應 0 V 到參考電壓。
VDDA
F103 給類比電路用的電源，也是 ADC 的參考電壓。Blue Pill 上它就是 3.3 V，和 MCU 同一個電源。
分壓
兩顆電阻串聯在 3.3 V 和 GND 之間，接點的電壓是兩者按比例分。兩顆一樣大時是一半，約 1.65 V，讀成約 2048。
浮接
floating：腳位什麼都沒接。輸入阻抗很高，讀到的電壓由雜訊和殘留電荷決定，會亂跳。
消抖 · debounce
機械按鍵按下或放開時，接點會在幾毫秒內彈跳好幾次。消抖就是「電位要穩定一段時間才算數」。
SysTick
Cortex-M 核心內建的計時器，每次數到 0 就產生一次中斷。這裡設成每 1 ms 一次。
快照 · snapshot
在某個時刻把幾個會變的值一次複製下來，之後都從複本拿。
錯位讀取 · torn read
一個多 byte 的值，各個 byte 來自不同時刻。例如 LOW 來自 0x7FF、HIGH 來自 0x800，合起來讀成 0x8FF。

四個新 register，版本只升 minor

位址 · 名稱內容
0x10 ADC_LOWPA0 的 12-bit 值的 bit 7:0
0x11 ADC_HIGHbit 11:8 放在 bit 3:0，bit 7:4 讀 0。值 = HIGH × 256 + LOW
0x12 BUTTON_STATEbit 0 PRESSED：按鍵按著（消抖之後）；bit 7:1 讀 0

四個都是 RO，寫入會在 STATUS 設 RO_WRITE。它們都放在原本讀 0xFF 的位址，其他 register 的意思一個都沒變，所以照 12-a 的版本規則，PROTOCOL_VERSION 從 0x10 升到 0x11（1.1）：只認得 1.0 的 driver 照樣能用。FW 版本 0.2 → 0.3。

BUTTON_PRESSES 是規劃裡沒有的。只有 BUTTON_STATE 的話，Jetson 每秒輪詢一次，中間按了一下又放開，就完全看不到。有了計數，Jetson 記住上次讀到的值，兩次相減（mod 256）就是這段時間按了幾下。它不能清除，因為「讀取清除」會撞上 TXE 預先取的 byte（12-a 的 STATUS 就是這樣決定的），「寫入清除」又會讓兩個讀它的程式互相干擾。

12b.4firmwareADC1

ADC：連續轉換，主迴圈搬運

  • ADC clock 12 MHz：F103 的 ADC 最高 14 MHz。APB2 是 72 MHz，能選的除數是 2、4、6、8，6 是不超過 14 MHz 的最快選擇。
  • 取樣 239.5 cycles，是最長的一檔。一次轉換是取樣時間加 12.5 cycles，(239.5 + 12.5) / 12 MHz = 21 µs。取樣久一點，內部的取樣電容充得比較滿，對訊號源的阻抗比較寬容。Jetson 一次讀取就要好幾百 µs，再快也沒有意義。
  • 連續轉換：啟動一次之後，ADC1 自己一直轉下去，firmware 不用每次觸發。代價是值一直在變，下一節要處理。
  • 校正：F103 的 reference manual 建議上電後做一次自我校正，補償內部電容的誤差。它也要求 ADON 設起來之後，至少等兩個 ADC clock 才開始校正（datasheet 的 tSTAB 約 1 µs）。第一版沒有等，板子上也沒出問題，是 code review 對照規格指出的，於是補上 delay_cycles()：72 MHz 下等 72 次迴圈，每次超過一個 cycle，所以至少 1 µs。
  • 參考電壓是 VDDA：讀到的是「PA0 佔 3.3 V 的比例」。分壓中點的比例只看兩顆電阻，3.3 V 本身偏一點，讀數不會跟著變。

為什麼放在主迴圈，不用 ADC 中斷？I2C 中斷要讀 target.adc，主迴圈要寫它。adc 是 uint16_t，Cortex-M3 用一條 STRH 指令寫完，I2C 中斷不可能看到「寫了一半」的值。主迴圈本來就空著（12-a 不用 __WFI()，原因見迴圈上方的註解），讓它搬資料剛好。

12b.5protocol快照

兩個 byte，必須來自同一次轉換

Jetson 照規格一次讀 2 個 byte：i2ctransfer w1@0x42 0x10 r2@0x42。firmware 分兩次 tx() 送出 LOW 和 HIGH，兩次之間如果換了一個轉換值，而且剛好跨過 0x800：

不能做的：讀到 LOW 時把 HIGH 鎖住

很多 sensor 晶片的做法是「讀 LOW 時把 HIGH 鎖存下來」。12-a 的 code review 預先指出這裡不能這樣做：Jetson 讀 0x0F 的 1 個 byte 時，TXE 會順便取 0x10（12-a 的圖 12.1），那個 LOW 沒送到 Jetson，卻觸發了鎖存。下一次 Jetson 真的讀 0x10、0x11，HIGH 就是很久以前鎖住的舊值。任何「讀到哪個 byte 才做某件事」的設計，都會被多取的那個 byte 誤觸發。

做法：在讀取開始時，一次拍下所有輸入

快照的時機是「Jetson 送出 0x42 + R 的那一刻」，和接下來讀了哪幾個 byte、有沒有多取一個完全無關。所以：

  • 一筆讀取裡的 LOW、HIGH、BUTTON_STATE、BUTTON_PRESSES 都是同一個時刻的值。
  • 讀 0x0F 時多取的 0x10 什麼都不觸發；下一筆讀 0x10 會重新拍一張。
  • 分成兩筆讀（先讀 0x10、再讀 0x11）就是兩張快照，可能來自不同轉換。register map 寫明：不要這樣讀。

快照的複製是在 I2C 中斷裡做的，會不會被打斷？主迴圈不會打斷中斷，adc 又是一次寫完的。SysTick 會改 button 和 presses，所以把它的優先權設成和 I2C1 同一級（12b.6），兩個中斷誰都不會打斷誰，快照不會拿到更新到一半的按鍵狀態。

下面的模擬器把同一個問題放大：A0 浮接，值在 2048 上下亂跳（12b.7 的實驗）。可以切換 firmware 用快照或讀即時值，以及兩種讀法：

模擬：瀏覽器裡的簡化模型，不是實機（數字模型見下方說明）
firmware 讀法
firmware 快照 讀法 w1 0x10 r2 錯位 0 / 0

      

      
模型：每次轉換是 1950–2150 之間的隨機值（浮接時實測 1966–2156）。ADC_HIGH 是第 2 個 byte 時，模型讓兩個 byte 來自同一次轉換（實測：變異版 2000 次 0 次錯位）；是第 3 個 byte 時，模型讓它來自約 4 次轉換之後（第 1 個 byte 送完要約 90 µs）。

踩過與差點踩的坑

      

        
以為中點會跨 0x800
症狀
把快照拿掉，實機測試照樣全綠。
後果
以為驗過「兩個 byte 一致」，其實什麼都沒驗。
正解
先看值有沒有跨過 HIGH byte 的邊界；用浮接的 A0 讓它跨過。

        
只用 2 byte 讀取找錯位

輸入跨過 0x800，變異版 2000 次照樣 0 次錯位。
後果
以為讀即時值也沒差，把快照當成多餘。

讓 ADC_HIGH 落在第 3 個 byte（w1 0x0f r3），兩次取值才隔得夠久。

        
讀 LOW 時鎖住 HIGH
症狀
讀了 0x0F 之後，下一次讀 ADC 的 HIGH 是很久以前的值。
後果
TXE 多取的 byte 觸發了鎖存，偶發的錯值極難追。

在讀取開始時拍快照，和讀了哪些 byte 無關。

        
把浮接的雜訊當成 ADC 雜訊

A0 沒接線時標準差 52.7，開始考慮做平均。
後果
為一個不存在的問題改規格（平均會改變值的意思）。

先確認接線；接上分壓後標準差 1.6–1.9，不需要平均。

        
兩顆電阻的腳碰在一起
症狀
沒人動，中點突然讀到 4095。
後果
上面那顆電阻被短路，中點直接等於 3.3 V。

Step 13 進到 Jetson 的 kernel：寫一個 I2C client driver edge_ctrl，用 Device Tree 綁到 0x42，至少把 device_id、firmware_version、adc、button、LED、status 開放給 userspace（sysfs 或 character device，選哪個要在那一步寫清楚理由），application 不再碰 /dev/i2c-*。這一章的規則會直接變成 driver 的寫法：ADC 一次讀 2 byte、先讀 PROTOCOL_VERSION 確認 major 是 1。

      
1. Jetson 先讀 0x10、再另外讀 0x11，拿到的值一定正確嗎？
不一定。兩筆讀取各拍一次快照，中間 ADC 可能已經換了值；如果剛好跨過 HIGH byte 的邊界，合起來會差 256。所以 register map 規定 ADC 要一次讀 2 byte。

      
2. 為什麼不在「讀到 ADC_LOW」時把 ADC_HIGH 鎖住？
F103 的 TXE 會在 Jetson NACK 之前多取一個 byte。讀 0x0F 的 1 個 byte 時，firmware 也會取 0x10、觸發鎖存，Jetson 卻沒讀到 LOW；之後真正讀 ADC 時，HIGH 是舊的。快照在讀取開始時拍，和取了哪些 byte 無關。

      
3. 分壓中點讀到 2068，用它能驗出錯位嗎？
不能。錯位只在值跨過 HIGH byte 的邊界時才看得出來，2068 附近的雜訊只有 ±10，HIGH 永遠是 0x08。要讓輸入跨過 0x800，例如讓 A0 浮接，而且讓 ADC_HIGH 是第 3 個 byte。

      
4. 按鍵在 5 ms 內彈跳了 6 次之後穩定按住，BUTTON_PRESSES 加幾？什麼時候加？
加 1。每次電位改變計數都從 1 重新開始，所以要等最後一次彈跳之後，低電位連續 20 ms（20 次取樣）才算按下，那時加 1。

      
5. 這一步的 PROTOCOL_VERSION 為什麼是 0x11 不是 0x20？
新增的四個 register 都在原本讀 0xFF 的位址，既有 register 的意思和 transaction 規則都沒變，只認得 1.0 的程式照樣能用，所以是 minor 加 1。
