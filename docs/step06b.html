不用 Python library 讀 INA219

6-a 讀懂了廠商範例，但它靠 python3-smbus 幫忙收發 byte。寫 kernel driver 之前，這一步把那層拿掉：先用 i2c-tools 的 i2cget / i2cset 手動讀寫 register，再寫一支 C++ 小工具 ina219_raw 直接對 /dev/i2c-7 發 ioctl，自己把兩個 byte 拼成 16-bit 值、自己換算成電壓和電流。目的是在寫 driver 前確認線、bus、位址、register map、byte order 都對。

6b.1起點為什麼

寫 driver 之前，先證明硬體這端沒問題

Step 7 的 kernel driver 一旦讀出奇怪的數字，可能的原因很多：DT 節點寫錯、probe 沒跑、位址錯、byte 順序錯、換算公式錯，或者線根本沒接好。這些問題混在一起就很難查。這一步先在 userspace 把「bus、位址、register 的值、換算」逐項確認，Step 7 出問題時，就只剩 driver 本身要查。

互動雙方：controller 仍是 Jetson 的 c250000.i2c（i2c-7，header pin 3 / 5），target 仍是 UPS 模組上的 INA219，位址 0x41。userspace 這一側換成兩種程式：i2c-tools 的指令，以及我們自己的 build/ina219_raw。兩者都透過 kernel 的 i2c-dev 打開 /dev/i2c-7。這一步不做：不寫 kernel driver、不用 hwmon（Step 7、8），工具也不寫入任何 register。

i2c-tools
Ubuntu 套件，包含 i2cdetect（掃描）、i2cget（讀）、i2cset（寫）等指令，都是直接打開 /dev/i2c-N 的 userspace 程式。
SMBus word
SMBus 規格定義的 16-bit 傳輸：「寫 register 編號、再讀 2 byte」。SMBus 規定低位 byte 先送，而 INA219 是高位先送，所以 i2cget ... w 讀到的值高低位是反的（6b.4）。
I2C_RDWR
i2c-dev 的 ioctl，一次送出一串 struct i2c_msg（每個 message 指定位址、方向、長度、buffer），kernel 把它們接成一筆 I2C transaction，中間用 repeated start 連接。它不解讀資料，byte 怎麼拼由我們自己決定。
repeated start
在同一筆傳輸中，不送 STOP、直接再送一次 START 並改變方向（寫→讀）。讀 INA219 register 就是「寫 pointer → repeated start → 讀 2 byte」。
big-endian
多 byte 數值的高位 byte 放前面（先送）。Jetson 的 CPU 是 little-endian（低位在前），所以不能把兩個 byte 直接當成一個 uint16_t 讀。
6b.2路徑兩種讀法

i2cget 和 ina219_raw 走同一條路，差在 ioctl

6-a 的 python3-smbus 用的是 I2C_SMBUS ioctl 的「I2C block read」，讀回的 byte 按線上的順序排，範例再自己拼成高位在前。這一步兩種工具各用一種 ioctl，正好對照出 byte order 是誰決定的。

6b.4手動讀i2cget

i2cget 讀到的 Config 是 0xef0e，不是 0x0EEF

用 i2cget 的 word 模式（最後一個參數 w）把六個 register 讀一遍：

for r in 0 1 2 3 4 5; do i2cget -y 7 0x41 $r w; done
0xef0e «1»
0x0000
0x9260 «2»
0x0000
0x0000
0xf468 «3»
  1. 1Config。6-a 確認過範例寫進去的是 0x0EEF，這裡高低 byte 對調了。
  2. 2Bus Voltage。對調後是 0x6092，(0x6092 >> 3) × 4 mV = 3090 × 4 mV = 12.360 V。如果不對調，0x9260 >> 3 = 4684，換算是 18.736 V，超過 3S 電池的 12.6 V 上限。
  3. 3Calibration，對調後 0x68F4 = 26868，和範例寫的一樣。

原因是 SMBus 規格：word 傳輸的第一個 byte 是低位。i2cget 照規格把「先到的 byte」當成低位，而 INA219 先送的是高位。改用 i 模式（I2C block read，照線上的順序列出 byte）就看得出晶片真正送了什麼：

i2cget -y 7 0x41 0x00 i 2
0x0e 0xef «1»
  1. 1先 0x0E 再 0xEF：高位先送。照 big-endian 拼起來就是 0x0EEF。

這不只是顯示的問題：拿 i2cget ... w 的值直接換算，電壓會錯成 18.736 V；寫 driver 時用 SMBus word 的 API（kernel 的 i2c_smbus_read_word_data()）也有同樣的問題，要再對調一次（kernel 有 i2c_smbus_read_word_swapped() 專門處理這種晶片，Step 7 會用到）。

這幾個值在你的板子上會不同：Bus Voltage 隨電池電量變，Shunt / Current / Power 在有電流時不是 0。Config 和 Calibration 是 0x0EEF / 0x68F4 的前提是範例跑過；剛上電、沒跑過範例時是上電預設值（Config 0x399F，datasheet；Calibration 0）。

6b.5手動寫i2cset

i2cset 也是低位先：只把原值寫回去

i2cset ... w 一樣照 SMBus 先送低位 byte。所以要讓晶片收到 0x68F4，指令要寫 0xf468，也就是 i2cget 讀到的那個樣子。這一步只做一次「寫回原值」的練習，不改任何設定：

i2cget -y 7 0x41 0x05 w; i2cset -y 7 0x41 0x05 0xf468 w; echo "exit $?"; i2cget -y 7 0x41 0x05 w
0xf468
exit 0 «1»
0xf468 «2»
  1. 1i2cset 成功時不印東西，結束碼 0。
  2. 2寫進去再讀回來一樣。因為讀和寫都用 SMBus word，兩次對調互相抵消；值本身沒變。

不要照 datasheet 的寫法直接 i2cset ... 0x68F4 w：晶片會收到 0xF468（62568），Current_LSB 變成原本的 0.43 倍，電流和功率都會算錯，直到再跑一次範例。這次沒有這樣寫過，數字是推算的。你的板子上 Calibration 不是 0xf468 時，把第一個 i2cget 讀到的值原樣放進 i2cset，才是「寫回原值」。

6b.6工具I2C_RDWR

ina219_raw：一次 ioctl 讀一個 register

工具的核心是 read_reg()：兩個 i2c_msg，第一個寫 1 byte（register pointer），第二個讀 2 byte，一起交給 I2C_RDWR。kernel 把它們接成一筆傳輸，中間是 repeated start，和圖 6.1 控制器那一格一樣。

  • 不用 ioctl(fd, I2C_SLAVE, addr)：I2C_RDWR 的每個 message 自帶位址，所以不需要先綁定位址。
  • ioctl() 回傳成功送出的 message 數，要等於 2 才算成功。位址沒有回 ACK 時 ioctl 失敗，errno 是 EREMOTEIO（6b.8）。
  • 只讀不寫：唯一寫出的 byte 是 register pointer（len = 1），寫入 register 要 3 byte（pointer + 2 byte 值），工具沒有這種 message。測試也把這條寫成規則。
  • byte order 只在 be16() 一處：不把 buf 用 memcpy 複製進 uint16_t，那樣得到的是 CPU 的 byte order（little-endian），結果和 i2cget ... w 一樣是反的。

6b.7換算整數

換算只用整數，兩條路算電流

換算放在 tools/ina219_decode.h，公式和 6-a 的範例相同，但寫法有兩點不同：

  • 只用整數，單位是 mV / µV / µA / µW。Step 7 會把同樣的算式搬進 kernel，而 kernel 裡不用浮點數。Current_LSB 寫成 40960000 / (Cal × R[mΩ]) µA：Cal 26868、R 10 mΩ 時是 152.45 µA。範例用的 0.1524 mA 是四捨五入過的（6a.5），所以兩者在大電流時差約 0.03 %。
  • 有號數用 static_cast<std::int16_t>，取代範例手寫的 value -= 65536。Shunt 和 Current 有號；Power 依 datasheet 是無號，不做符號轉換（範例有做，6a.6）。
  • 電流有兩條路：current_uA_from_shunt() 直接用歐姆定律（Vshunt / R），不需要 Calibration；current_uA() 用晶片算好的 Current register。晶片內部算的是 Current = Shunt × Cal / 4096，所以兩者應該相差不到一個 Current_LSB。Calibration 是 0（剛上電）時，Current register 恆為 0，工具改印 n/a，只剩第一條路可用。

Rshunt = 0.01 Ω 仍是範例註解的假設，這一步沒有拆模組量電阻，沒有查證。register 的完整說明整理在 docs/ina219-registers.md，Step 7 寫 driver 時以它為對照。

cmake -S . -B build >/dev/null && cmake --build build --target ina219_raw && build/ina219_raw

  1. 1六個值正好是 6b.4 i2cget 讀到的對調：0xef0e → 0x0EEF、0x9260 → 0x6092、0xf468 → 0x68F4。兩種工具各用一種 ioctl，結果互相印證。
  2. 23090 × 4 mV = 12.360 V，在 3S 電池的 9～12.6 V 內。6-a 用範例讀到 12.364 V（3091），差 1 個 LSB，是電池電壓本身的變化。
  3. 3電流 0：DC adapter 接著、電池已充飽，shunt 上沒有電流（同 6a.11）。兩條路都是 0，所以這次沒辦法驗證兩條路在有電流時一致，要等拔掉 adapter（6b.10）。

模組不在時要明確回報錯誤。遠端登入時沒辦法拔線（而且 UPS 正在供電給 Jetson），所以用一個沒有裝置的位址 0x45 模擬「沒有 ACK」：

build/ina219_raw --addr 0x45; echo "exit $?"; build/ina219_raw --addr 0x80; echo "exit $?"
/dev/i2c-7 addr 0x45 reg 0x00: Remote I/O error «1»
exit 1
usage: build/ina219_raw [--bus N] [--addr 0x03..0x77] «2»
exit 2
  1. 1沒有 ACK → EREMOTEIO（errno 121）。訊息指出是哪條 bus、哪個位址、讀到第幾個 register 時失敗，沒有印出任何數字。真的把模組拔掉時應該是同一個錯誤，但沒有實測。
  2. 20x80 不是 7-bit 位址，算用法錯誤，結束碼 2。0x00–0x02、0x78–0x7f 是 I2C 保留位址，也不接受。

跑出來不一樣時：open /dev/i2c-7: Permission denied 代表使用者不在 i2c 群組；0x41 也是 Remote I/O error 代表模組沒接上或位址不同（先 i2cdetect -y -r 7）；current (reg): n/a 代表晶片剛上電、還沒有人寫 Calibration，跑一次 6-a 的範例就會有值。

6b.9測試red → green

測試向量從 datasheet 和實機讀值來

兩個測試檔，都在工具寫好之前寫：

  • tests/test_ina219_decode.cpp：7 組換算向量，期望值取自 datasheet 和 6-a 在實機讀到的值（0x0E 0xEF → 0x0EEF、0x609A → 12364 mV），不是從 decoder 的輸出抄。包括狀態位（CNVR、OVF）、有號數的邊界（0x8000 → −327680 µV）、Current_LSB 由 Cal 算、Power 無號、兩條電流路徑差 ≤ 1 個 LSB。結束碼 0 / 1。
  • tests/test_ina219_raw.py：共 16 個案例。建置並跑上面的向量（1）；原始碼契約（4）：用 I2C_RDWR、不用 I2C_SMBUS、唯一的寫入長度是 1、byte order 只靠 be16()、decoder 裡沒有 float / double；CLI（3）：參數錯回 2、位址要是 7-bit、bus 不存在回 1；驗收腳本（4）；實機（4，EDGE_INA219_HW=1 才跑）：六個值不是全 0xFFFF 或全 0、Config 和 Calibration 等於 i2cget 對調後的值、電壓在 9～12.8 V、0x45 回報 Remote I/O error。

紅燈紀錄：工具和 header 不存在時 4 failures + 3 errors；驗收腳本的 4 條在腳本寫好前 1 failure + 3 errors。寫好之後只有一條紅：是我自己把向量算錯（6b.11）。為了確認向量真的守得住，把 decoder 改壞 7 種（兩個 byte 對調、右移 2 位、CNVR 看錯 bit、shunt 和 current 當無號、power 少乘 10、歐姆定律少一個 0），每一種都讓向量測試失敗。

python3 -m unittest discover -s tests -p 'test_ina219_raw.py' -v
EDGE_INA219_HW=1 python3 -m unittest discover -s tests -p 'test_ina219_raw.py' -v

第一行不碰硬體（會自己用 CMake 建置，實機 4 個 skip）；第二行要有 UPS 模組接在 bus 7，全程只讀。

6b.11常見錯誤

踩過的坑

相信 i2cget w 印出來的值

症狀
Config 讀到 0xef0e、Bus Voltage 0x9260。
後果
以為晶片設定被改了；電壓算成 18.736 V。
正解
SMBus word 是低位先；對調，或用 i 模式看線上的 byte。

i2cset 照 datasheet 的值寫

症狀
i2cset ... 0x05 0x68F4 w。
後果
晶片收到 0xF468，電流和功率全錯（推算，沒有真的寫過）。
正解
word 模式的值要先對調；這一步只寫回讀到的原值。

把兩個 byte memcpy 進 uint16_t

症狀
程式裡 memcpy(&v, buf, 2)。
後果
在 little-endian 的 Jetson 上得到和 i2cget w 一樣的反值。
正解
be16()：b[0] << 8 | b[1]，和 CPU 無關；測試禁止 memcpy(&。

測試向量自己算錯

症狀
bus_mV(0xFFF8) 期望 32760，實作回 32764，測試紅。
後果
差點去「修」正確的實作。
正解
0xFFF8 >> 3 = 8191，× 4 = 32764，錯的是向量。改完再做變異測試，確認向量守得住。

Current 是 0 就以為沒電流

症狀
剛上電讀 Current register 一直是 0。
後果
誤判成負載沒在耗電。
正解
Calibration 是 0 時晶片不算電流；工具印 n/a，改看 Vshunt / R 那一行。

讀不到時印出一堆 0

症狀
模組不在，程式照樣印表格。
後果
0 V、0 A 看起來像「電池沒電」。
正解
任一 register 讀失敗就印 Remote I/O error 並以 1 結束，不印數字。

這一步做到了什麼

  • 用 i2cdetect -l 由控制器名稱找到 bus 7，i2cdetect -y -r 7 找到 0x41。
  • 用 i2cget 讀完六個 register，看清楚 SMBus word 的 byte 順序；i2cset 寫回原值。
  • 不用 Python library 的 ina219_raw：I2C_RDWR 讀、be16() 拼、整數換算，結果和 i2cget 對調後一致；位址沒回應時明確回報 I/O error。
  • 測試 16 個（含 4 個實機）加 7 組換算向量；驗收 0 failure（--no-unplug）。
  • 沒有實測：拔掉 DC adapter 時的電流、實際拔掉 INA219 時的錯誤（遠端登入）。
  • 沒有查證：shunt 電阻值（0.01 Ω 是範例註解的假設）。

下一章 Step 7 把這一章的操作搬進 kernel：寫一個 struct i2c_driver，在 overlay 裡為 c250000.i2c 加一個 ina219@41 節點讓 kernel 建立 I2C client、呼叫 probe()，預計用 kernel 的 SMBus API 讀 register（要處理和 6b.4 同樣的 byte order），換算沿用 ina219_decode.h 的整數算式。這一章的工具就是它的對照組：driver 讀到的值應該和 ina219_raw 一樣。

1. i2cget -y 7 0x41 0x02 w 印出 0x9260。電池電壓是多少？

先對調成 0x6092，右移 3 位得 3090，× 4 mV = 12.360 V。不對調會算成 18.736 V。

2. 為什麼 ina219_raw 不需要先 ioctl(fd, I2C_SLAVE, 0x41)？

I2C_RDWR 的每個 i2c_msg 都自帶位址；I2C_SLAVE 是給 read() / write() 和 I2C_SMBUS 用的「預設位址」。

3. Calibration 是 0 時，還有辦法算出電流嗎？

有。Shunt Voltage 是直接量到的，I = Vshunt / Rshunt，不需要 Calibration；只是要知道 Rshunt（這裡假設 0.01 Ω）。Current register 則一直是 0。

4. 想用 i2cset 把 Calibration 設成 26868（0x68F4），word 模式要給什麼值？

0xf468。SMBus word 先送低位 byte，所以要先對調，晶片才會先收到 0x68。
